# 微信支付接入说明（1.1.31）

顾客在小程序里下单后可直接用微信支付；后台退款原路退回微信。H5 网页版仍是“联系门店付款”。

**商户资料配置完成之前，系统自动保持“门店确认收款”**，不会出现无法下单的情况。代码可以先上线，资料齐了再打开。

## 一、需要你在微信侧准备的

1. **微信支付商户号**：在微信支付商户平台（pay.weixin.qq.com）开通。服务类目需与门店经营范围一致；涉及医疗美容的项目，按微信支付要求提供相应资质。
2. **把商户号和小程序关联**：商户平台 →「产品中心」→「AppID 账号管理」→ 关联小程序 AppID `wx1e9453a0ddc8385d`；再到小程序后台（mp.weixin.qq.com）→「微信支付」确认关联。
3. **在商户平台「账户中心 → API 安全」准备四样东西**：
   - **APIv3 密钥**：自己设置的 32 位字符串；
   - **商户 API 证书**：下载后得到 `apiclient_key.pem`（商户私钥），并记下证书序列号；
   - **微信支付公钥**：申请后下载 `pub_key.pem`，并记下公钥 ID（以 `PUB_KEY_ID_` 开头）。
     - 老商户如果只有“平台证书”、没有微信支付公钥，也能用，系统会自动下载平台证书。但建议申请公钥。

这些资料等同于收款账户的钥匙，**只放在服务器上**，不要发到聊天、邮件或代码仓库里。

## 二、服务器配置（由你或运维操作）

1. **上传密钥文件**：把 `apiclient_key.pem`、`pub_key.pem` 上传到 `/opt/anqi/shared/wechatpay/`，并设置权限：
   ```
   chown -R anqi:anqi /opt/anqi/shared/wechatpay && chmod 700 /opt/anqi/shared/wechatpay && chmod 600 /opt/anqi/shared/wechatpay/*.pem
   ```
2. **配置环境变量**：在 `/opt/anqi/shared/business.env` 末尾加上下面这些。`WECHAT_APPID` 已存在，确认它就是上面那个小程序 AppID 即可。
   ```
   PAYMENT_MODE=wechat
   WECHAT_PAY_MCHID=商户号
   WECHAT_PAY_SERIAL_NO=商户API证书序列号
   WECHAT_PAY_PRIVATE_KEY_FILE=/opt/anqi/shared/wechatpay/apiclient_key.pem
   WECHAT_PAY_API_V3_KEY=32位APIv3密钥
   WECHAT_PAY_PUBLIC_KEY_ID=PUB_KEY_ID_开头的公钥ID
   WECHAT_PAY_PUBLIC_KEY_FILE=/opt/anqi/shared/wechatpay/pub_key.pem
   WECHAT_PAY_NOTIFY_URL=https://anqiht.okam.top/api/pay/notify
   ```
3. **核对配置**：运行下面的命令。它不下单、不扣款，只用商户证书向微信查询一个不存在的订单。
   ```
   cd /opt/anqi/business && /opt/anqi/node/bin/node --env-file=/opt/anqi/shared/business.env tools/wechat-pay-check.cjs
   ```
   显示“微信支付配置核对通过”才继续下一步。
4. **重启并确认**：
   - 执行 `systemctl restart anqi-business`；
   - 打开 `https://anqiht.okam.top/api/health`，应显示 `"paymentMode":"wechat"`；
   - 如果显示 `off`，用 `journalctl -u anqi-business -n 50` 查看日志里“微信支付未启用，缺少或无效的配置：…”这一行，按提示补齐。
5. **试付一笔**：用小程序体验版下一笔小额订单并付款，再在后台对这笔订单点「售后退款」，确认钱原路退回。

回调地址 `/api/pay/notify` 由 nginx 直接转给业务服务。这条规则随 1.1.31 发布脚本自动添加，也可以单独执行 `tools/wechat-pay-nginx.sh`。

## 三、上线后的业务规则

- **付款**：
  - 下单后 2 小时内可付款，超时自动关闭微信订单并取消，库存恢复。
  - 付款结果以微信回调为准，回调要验签、解密，并核对商户号、小程序、订单号和金额，任何一项不符都不入账。
  - 回调没收到时，小程序付款完成后会主动查询；系统每分钟也会对账一次。
- **取消订单 / 门店确认收款**：都会先关闭微信订单。如果发现顾客其实已经付款，会自动按微信付款入账，并提示不要再收一次。
- **退款**：
  - 后台「订单管理 → 售后退款」，微信付款的订单原路退回；
  - 退款进度（处理中 / 已到账 / 异常）显示在订单详情；
  - 套餐已有核销记录时不能整单退款，规则和之前一样；
  - 门店线下收款的订单退款仍按线下处理。
- **对账**：
  - 「支付审计」记录每一步：发起支付、入账、拒绝、重复付款、发起退款、退款到账。
  - 极少数情况下，顾客对同一订单既付了微信又付了线下，订单详情会显示“重复付款，请在微信支付商户平台退还”。
- **推荐奖励、分红池**：微信付款和门店确认收款一样，都在付款时计算，规则不变。

## 四、停用

把 `business.env` 里的 `PAYMENT_MODE` 改回 `off` 并重启业务服务，即恢复“门店确认收款”。已付款订单和退款记录不受影响。
