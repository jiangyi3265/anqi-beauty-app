# 三端协作开发

## 仓库分工

| 仓库 | 负责内容 | 本地端口 |
| --- | --- | --- |
| [anqi-beauty-app](https://github.com/jiangyi3265/anqi-beauty-app) | UniApp 小程序/H5，`server/` 中的 Node 业务规则与数据存储 | H5 5173，Node 3016 |
| [anqi-beauty-admin](https://github.com/jiangyi3265/anqi-beauty-admin) | Vue 管理后台，商品、门店、会员、订单和预约管理 | 建议 5174 |
| [anqi-beauty-backend](https://github.com/jiangyi3265/anqi-beauty-backend) | Java 认证、权限、菜单及业务接口代理 | Java 8080 |

用户业务接口由 Node 提供；管理后台通过 Java 认证、权限校验后转发业务请求到 Node。用户端 `/api` 可直接代理到 Node，或经过 Java 的公开业务接口代理，具体由部署网关配置决定。Java 与 Node 通过内部密钥通信；库存、领取资格及预约校验的修改主要在 app 仓库的 `server/`。

## 获取代码

```sh
git clone https://github.com/jiangyi3265/anqi-beauty-app.git
git clone https://github.com/jiangyi3265/anqi-beauty-admin.git
git clone https://github.com/jiangyi3265/anqi-beauty-backend.git
```

建议使用 Node.js 24 LTS；Java 使用 JDK 8、Maven，并准备本地 MySQL 和 Redis。两个前端都使用 `npm ci` 按各自的锁文件安装依赖。

## 本地运行用户端与业务接口

在 app 仓库执行 `npm ci`，复制 `.env.example` 为 `.env`。本地配置说明：

- `HOST=127.0.0.1`、`PORT=3016`，`NODE_ENV=development`。
- `ADMIN_PASSWORD` 填本地独立随机值，否则服务拒绝启动。
- `DB_NAME` 留空时使用 `server/data/db.json`；联调 MySQL 时填写本地数据库配置。
- `INTERNAL_SECRET` 与 Java 的 `ANQI_INTERNAL_SECRET` 保持一致。
- 本地保持 `PAYMENT_MODE=off`；真实微信登录需要开发者单独配置微信凭据。
- `VITE_API_BASE=http://127.0.0.1:3016/api` 直连本地业务服务；需要经过 Java 时改为 `http://127.0.0.1:8080/api`。

两个终端分别执行：

```sh
npm run server
```

```sh
VITE_API_BASE=http://127.0.0.1:3016/api npm run dev:h5
```

默认访问 `http://127.0.0.1:5173`。小程序真机无法访问开发电脑的 `127.0.0.1`；真机联调需使用已配置合法域名的 HTTPS 测试服务。

## 本地运行 Java 与后台

1. 在本地空数据库中按顺序导入 backend 仓库的 `sql/ry_20250522.sql`、`sql/anqi-deployment-menus.sql`、`sql/anqi-staff-scheduling.sql`、`sql/anqi-income-config.sql`，使用 UTF-8。前两个初始化脚本只用于新开发库；已有数据库升级只需执行后两个菜单脚本（详见 backend 的 `sql/README.md`）。
2. 参考 backend 的 `.env.example`，在 IDE 或进程环境中配置 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`TOKEN_SECRET`、`ANQI_BUSINESS_URL` 和 `ANQI_INTERNAL_SECRET`。Spring Boot 不会自动加载该 `.env` 文件。
3. 配置本地 Redis；通过 `RUOYI_PROFILE` 指定可写上传目录。`ANQI_BUSINESS_URL` 默认指向 `http://127.0.0.1:3016`。
4. 在 backend 仓库执行：

```sh
mvn -pl ruoyi-admin -am package -DskipTests
java -jar ruoyi-admin/target/ruoyi-admin.jar
```

在 admin 仓库另开终端：

```sh
npm ci
npm run dev -- --port 5174
```

访问 `http://localhost:5174`。后台 `/dev-api` 由 Vite 代理到 Java 的 `http://localhost:8080`。初始管理员没有固定密码，需按 backend 的 `sql/README.md` 设置独立 BCrypt 哈希后登录，正式环境凭据另行提供。

## 分支与跨仓库变更

每位开发者从更新后的 `main` 创建功能分支，推送分支后通过 Pull Request 合并：

```sh
git switch main
git pull --ff-only
git switch -c feature/your-feature
# 修改后执行对应验证
git add <本次改动文件>
git commit -m "feat: describe the change"
git push -u origin feature/your-feature
```

接口字段变动应同时更新 `docs/API.md`、用户端调用和管理后台表单；在各仓库 PR 中注明配套 PR 或提交。涉及已有订单、领取记录及门店信息时，使用兼容迁移并保留记录 ID，避免重新初始化数据。

## 验证与构建

app 仓库：

```sh
node tools/trial-booking-acceptance.cjs
VITE_API_BASE=https://anqiht.okam.top/api npm run build:h5
VITE_API_BASE=https://anqiht.okam.top/api npm run build:mp-weixin
```

预约验收脚本使用独立临时数据和测试微信登录，覆盖领取、预约、权限、容量、核销、门店和旧数据迁移，不连接正式数据库。小程序产物在 `dist/build/mp-weixin`，H5 在 `dist/build/h5`。

admin 仓库执行 `npm run build:prod`，产物在 `dist/`。三个仓库提交前执行 `git diff --check`。

## 配置与交付边界

六档 VIP 套餐、三种体验卡、员工排班、静态/动态收益规则和账本已包含在源码中。收益默认不开启，由运营配置；真实微信在线支付和提现转账尚未实现。

`.env`、私钥、数据库、上传文件、登录二维码、验证截图和构建产物不提交。admin 的 `.env.development`、`.env.production` 仅包含公开构建参数，可以提交；微信 AppSecret 和任何密钥不能写入 `VITE_*`。

参见 [接口文档](API.md)、[后台使用说明](后台使用说明.md)、[员工排班使用说明](员工排班使用说明.md) 和 [收益配置使用说明](收益配置使用说明.md)。生产部署与小程序上传单独执行，推送 GitHub 不会自动更新线上服务。
