# 员工排班（1.1.22）

## 开启顺序

1. 在管理后台「员工排班 → 员工档案」添加真实员工，填写姓名、职务及可选手机号。
2. 切换「班次安排」，选择员工、门店、日期和起止时间。一次最多选择31个日期，批量保存为独立班次。
3. 在「门店管理」设置每次预约占用时长（15至480分钟，默认60分钟），启用「按员工排班开放预约」。
4. 顾客通过体验卡或已付款服务预约时，只能选择有员工出勤且名额未满的时段；可指定员工，也可自动安排。

现有门店默认不启用排班，不会因升级突然无法预约。正式环境不导入测试员工或测试班次。其他后台角色需要分配 `anqi:staff:list`、`anqi:staff:edit` 以及门店查看权限 `anqi:stores:list`；不会自动扩大已有角色的权限。

## 预约与调整规则

- 使用北京时间。跨天班次拆成两天，午休拆成上午、下午两段。
- 同一员工跨门店也不能在重叠时段出勤；录入休假前先缩短或移除相应出勤段。
- 员工同时只能接待一个预约，按完整服务时长判断冲突。门店仍受店铺配置中的预约名额上限限制。
- 预约会保存当时的员工姓名、门店信息和占用时长。后续重命名员工不改写历史记录。
- 有未结束预约时，不能删除其班次、改为休假、缩短覆盖时段或停用员工；先在预约管理中取消或完成相关预约。
- 取消预约会释放时段。已经结束的班次不可修改或删除。
- 开启排班前已产生的未分配员工预约会保留，重叠时段保守停止接受新预约。
- 自动安排按当天有效预约数量从少到多选择可用员工；不包含自动生成轮班表、员工绩效或工资计算。

## 开发与部署

- 用户可用时段：`POST /api/appointment-options`，需登录并持有对应体验卡项目或可预约订单，参数与预约相同但只需 `date`，不需 `time`。
- 提交预约：`POST /api/appointments` 可选 `staffId`；服务端重新校验，不能依赖之前查询的时段。
- 后台员工：`/anqi/staff`；班次：`/anqi/shifts`；批量新增：`POST /anqi/shifts/batch`。
- Node 内部接口对应 `/api/admin/*`，使用原有内部鉴权；Java 负责后台角色权限。
- MySQL 自动增加 `anqi_staff`、`anqi_shifts` 数据表。菜单增量 SQL：后端仓库 `sql/anqi-staff-scheduling.sql`。
- 业务事务覆盖可用性校验与预约写入，防止并发重复分配员工；JSON 模式也串行执行并在失败时回滚。

## 收益功能边界

静态收益、动态收益尚未实现，不能把收益展示页或已有记录接口当作完成结算。
待提供六档套餐各自静态收益的产生条件、金额或比例、周期与期限，以及动态收益的受益人、层级、比例或金额、入账时点、退款冲回规则。当前不新增、不计算、不发放此类收益。
